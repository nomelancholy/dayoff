# 회원 쿠폰 주문 확인 화면 — 개발 미리보기

## 구현 범위

- 상품 상세의 직접 구매와 장바구니 선택 상품이 `/order-review`로 연결됩니다.
- 상품/옵션 ID, 수량만 세션 저장소에 보관하며 가격은 항상 서버에서 조회합니다.
- `POST /shop/order-review`는 검증된 로그인 사용자에게 발급된 미사용 쿠폰만 반환합니다.
- 기존 CouponService의 유효기간·활성화·사용 한도·최소 주문금액 검증을 재사용합니다.
- 최대 할인 쿠폰을 기본 선택하며 동일 할인액이면 먼저 만료되는 쿠폰을 우선합니다.
- 상품 금액, 쿠폰 할인, 할인 후 상품 금액, 기본 배송비, 예상 총액을 구분합니다.
- 기존 자체 주문서와 동일하게 할인 후 10만 원을 무료배송 기준으로 미리 계산합니다.
- 미리보기는 쿠폰·주문·재고를 쓰지 않으며 네이버 주문등록을 호출하지 않습니다.

## 공개 상태

운영 미배포. 구매 진입 버튼과 화면은 `import.meta.env.DEV`일 때만 표시됩니다.
서버도 `ORDER_REVIEW_PREVIEW_ENABLED=true`로 명시적으로 켜야 조회할 수 있습니다.
결제 버튼은 의도적으로 비활성화되어 있습니다. 이 단계는 할인 결제 구현 완료가 아닙니다.
운영 애플리케이션 ID/시크릿은 현재 발급 대기 상태입니다(2026-10-20 사용자 확인).

## 결제 연결 전 남은 작업

1. 운영 주문관리 API 인증정보 적용 및 읽기 조회 검증.
2. 할인된 가격을 주문형 basePrice로 전달하는 방식의 호환성 확인. 공식 안내의 자사몰 쿠폰 미지원 설명만으로 선할인 전송의 가능·불가능을 단정하지 않습니다.
3. 동일 쿠폰 중복 주문서 생성 방지, 미결제 주문서의 유효기간/폐기 시점 확인, 안전한 예약 해제.
4. merchantCustomCode 등으로 사이트 쿠폰 예약과 네이버 상품주문을 연결하고 결제 완료 시 사용 확정.
5. 전체/부분취소, 수량 변경, 재주문 및 원 단위 할인 배분 검증. 부분취소 시 쿠폰을 중복 복원하지 않아야 합니다.
6. 100% 할인 등 0원 상품, 수량에 나누어떨어지지 않는 정액 할인, 상품 정보 XML의 가격 일관성 처리.
7. 결제 상태 수집 지연/실패 시 쿠폰을 재사용시키지 않는 정책과 복구 절차.
8. Sandbox에서 실제 결제·취소까지 검증한 뒤 공개 화면/안내 문구 전환.

- 직접 구매/장바구니 진입, 최대 할인 선택, 수동 선택·해제, 새로고침, 로그아웃 시 쿠폰 격리 확인.
- 운영 결제나 실제 회원 쿠폰/재고는 변경하지 않았습니다.
